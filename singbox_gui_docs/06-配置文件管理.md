# 06 配置文件管理

## 6.1 数据模型

配置（Profile）元数据存于 `settings.db` 表 `profiles`，内容存于文件。

| 列 | 类型 | 约束/默认 | 说明 |
|---|---|---|---|
| id | INTEGER | 主键自增 | |
| name | TEXT | NOT NULL | 显示名，全局唯一（见 6.3.4） |
| order | INTEGER | NOT NULL | 排序，从 0 起 |
| type | INTEGER | NOT NULL，默认 0 | 0 本地，1 iCloud（仅兼容，见 15.5），2 远程 |
| path | TEXT | NOT NULL | 相对数据目录的路径：`configs/config_<id>.json` |
| remoteURL | TEXT | 可空 | 远程地址 |
| autoUpdate | BOOLEAN | NOT NULL，默认 false | 自动更新 |
| autoUpdateInterval | INTEGER | NOT NULL，默认 0 | 分钟；0 表示使用默认 60 |
| lastUpdated | DATETIME | 可空 | 远程最后成功更新时间 |

- 内容文件：`%APPDATA%\sing-box\configs\config_<id>.json`，UTF-8，无 BOM；写入采用“临时文件 + 原子替换”。
- `<id>` 取“下一个 ID”（`max(id)+1`，空表为 1），先写文件后插入记录。
- 删除配置：删除记录与内容文件；若删除的是选中配置，`selected_profile_id` 改为列表第一项（无则 -1）；若服务正以其运行，不自动停止。

## 6.2 新建配置入口（New Profile 菜单工作表）

从仪表“配置”卡加号、配置选择工作表打开。工作表最小 500×400：
- 顶部标题“新建配置”（headline，左右内边距 20，上 20，下 12）。
- 表单区一个分节，三个表单按钮（整行可点，左图标右文字）：
  1. “从文件导入”（doc.badge.plus）：打开文件对话框，过滤 `*.bpf;*.json`，单选。
     - `.json`：以文件名（去扩展名）为名称，打开“新建配置”表单（6.3）并预设为本地 + 导入 + 已选文件。
     - `.bpf`：读取并解码（ApplicationService.`DecodeProfile`），弹出“导入配置 / 确定要导入配置 {名称} 吗？”，确认后导入（6.3.5）并关闭工作表；失败动作名 “import profile”；读文件失败动作名 “read imported profile file”。
  2. “扫描二维码”（qrcode.viewfinder）：打开扫码工作表（6.9）。
  3. “手动创建”（square.and.pencil）：打开“新建配置”表单。
- 底部栏：分隔线 + 右侧“取消”。背景 controlBackground，内边距 16。
- 任一路径创建成功：将新配置设为选中（`selected_profile_id`），关闭全部相关工作表。

## 6.3 新建配置表单（New Profile / Import Profile）

### 6.3.1 布局
- 标题：普通为“新建配置”，由导入请求（深链接、扫码）打开时为“导入配置”。
- 工具栏：左“取消”，右“创建”（保存中替换为旋转指示器）；保存中整个表单禁用。
- 分节一（分组表单，标签左对齐、控件右对齐）：

| 字段 | 控件 | 显示条件 | 校验 |
|---|---|---|---|
| 名称 | 文本框，占位“必填” | 总是 | 非空，否则“缺少配置名称” |
| 类型 | 弹出选择：本地 / 远程（iCloud 选项见 15.5） | 总是 | |
| 文件 | 弹出选择：新建 / 导入 | 类型 = 本地 | |
| 文件路径 | 行：标签“文件路径” + 已选文件名按钮（点击重选）或“选择”按钮 | 类型 = 本地 且 文件 = 导入 | 未选文件时创建报“缺少文件” |
| URL | 文本框，占位“必填”，关闭自动更正 | 类型 = 远程 | 非空，否则“缺少 URL” |
| 自动更新 | 开关，默认开 | 类型 = 远程 | |
| 自动更新间隔 | 数字文本框，占位“分钟”，默认 60 | 类型 = 远程 | 整数；< 15 时按 15 生效（6.6） |

- 分节二：iOS 有“创建”按钮；Windows 与 macOS 一致，不显示（由工具栏“创建”承担）。

### 6.3.2 本地配置创建
1. 内容：导入则读取所选文件（UTF-8），新建则为 `{}`。
2. ApplicationService.`CheckConfig(content)`，失败显示错误（动作名 “create profile”）。
3. 写入 `configs/config_<nextID>.json`。

### 6.3.3 远程配置创建
1. 按 6.6.2 规则 HTTP GET 远程 URL。
2. `CheckConfig` 校验。
3. 写入内容文件；`remoteURL` = URL；`lastUpdated` = 现在。

### 6.3.4 名称唯一化
若名称已存在，依次尝试 `名称 (1)`、`名称 (2)` … 取第一个不存在的。

### 6.3.5 导入 .bpf / QRS 内容
- 解码得到 `ProfileContent{type, name, config, remote_path, auto_update, auto_update_interval, last_updated}`。
- QRS 导入在写入前先 `CheckConfig`；.bpf 文件导入不校验（与基线一致）。
- 写入内容文件，名称唯一化，类型按 content.type（LOCAL→本地，ICLOUD→本地（15.5），REMOTE→远程）；`last_updated` > 1e11 视为毫秒，否则为秒；为 0 则为空。
- 导入后设为选中配置，发出“配置列表已变更”事件。

## 6.4 编辑配置（Edit Profile 工作表）

最小 500×400：
- 标题“编辑配置”（同 6.2 标题样式）。
- 表单：名称、类型（只读显示：本地/远程）、URL（远程）、自动更新（远程）、自动更新间隔（远程）；远程额外分节“状态”：行“最后更新”= 相对时间。
- 底部栏（分隔线 + `HStack(spacing:12)`，内边距 16，controlBackground）：
  - 左：非远程为“编辑内容”，远程为“查看内容”——打开内容编辑窗口（6.5）。
  - 右：“取消”；“保存”（强调样式；未修改或保存中禁用）。
- 修改名称、URL、自动更新、间隔即标记“已修改”。
- 保存：更新记录 → 重新配置自动更新计时器（6.6.1）→ 若为选中配置且服务已连接则 `ReloadService` → 发出变更事件。失败动作名 “save profile”。

## 6.5 内容编辑窗口（Edit Content / View Content）

- 独立窗口，默认 700×500，最小 600×400；标题“编辑内容”或“查看内容”（只读，远程配置）；同一配置同一模式只开一个窗口，重复打开时激活。
- 加载中显示旋转指示器；加载失败动作名 “load profile content”。
- 编辑器：MyGo `ui/editor`，JSON 语法高亮，等宽字体（字体与字号取“设置 → 应用 → 编辑器字体”，见第 11 章），显示行号、折叠、查找替换（Ctrl+F / Ctrl+H）。
- **补全**：启动时通过 ApplicationService.`GenerateConfigSchema` 获取 JSON Schema（缓存于内存）。按光标所在 JSON 路径提供：
  - 键补全：当前对象可用属性（含 oneOf/anyOf 变体合并）。
  - 值补全：枚举值、布尔值、对象/数组骨架。
  - 引用补全：引用类字段补全文档中已有标签，引用种类与来源路径：outbound → `outbounds`、`endpoints`；inbound → `inbounds`；dns_server → `dns.servers`；rule_set → `route.rule_set`；certificate_provider → `certificate_providers`；http_client → `http_clients`；network_namespace → `network_namespaces`。排除当前正在编辑的对象自身的标签。
  - 只有一项且为纯值补全时自动关闭弹层。
- **校验**：文本变化后 2 秒防抖调用 `CheckConfig`；补全弹层可见时推迟；文本变化时（弹层不可见）先清除旧错误；弹层关闭后重新计时。
- **底部工具条**（仅可编辑时）：
  - 错误横幅（有错误时）：exclamationmark.triangle.fill（红）+ 错误文本（footnote，最多 2 行）+ 关闭 ×；内边距 12/8；controlBackground 圆角 8；左右外边距 8。
  - 符号条（可横向滚动，`HStack(spacing:4)`，内边距 8/6，controlBackground 圆角 8，外边距左右 8、下 8）：撤销、重做（不可用时禁用）、格式化（ApplicationService.`FormatConfig`，失败显示于错误横幅）| 竖分隔 | 插入符号 `"` `:` `,` `{` `}` `[` `]` `true` `false`（等宽 medium；单字符最小宽 24）。
- 窗口工具栏：“保存”（Ctrl+S，未修改时禁用；失败动作名 “save profile content”）、“复制”（复制全文到剪贴板）。
- 保存后：若为选中配置且服务已连接则 `ReloadService`。
- 关闭（✕、Esc、Ctrl+W）且有未保存修改：警告“未保存的更改 / 是否要保存所做的更改？”按钮“不保存”（破坏性）/“取消”/“保存”（保存成功后关闭）。

## 6.6 远程配置更新

### 6.6.1 自动更新计时器
- 启动时与任何配置保存/新增/删除后重新配置。
- 取所有“远程且自动更新”的配置；为空则不启用计时器。
- 周期 = min(各配置间隔)，间隔 = `autoUpdateInterval` 分钟（0 则 60 分钟），周期下限 15 分钟。
- 首次触发时间 = min(各配置 `lastUpdated + 间隔`)，早于现在则立即。
- 每次触发：逐个检查，若 `lastUpdated > 现在 − 间隔` 则跳过，否则更新（6.6.3）；单个失败只记日志，不弹窗。

### 6.6.2 HTTP 请求
- 方法 GET，最低 TLS 1.2，跟随重定向，TLS 握手超时 15 秒（与核心 TCP 超时一致），不设整体超时。
- `User-Agent: sing-box for Windows (sing-box <核心版本>; language <区域标识>)`。区域标识为界面语言的下划线形式，如 `zh_CN`（应用名称待定 A-10）。
- 核心版本取 DesktopService `GetDaemonInfo` 的版本；守护进程不可用时用构建时嵌入的核心版本常量（与随附守护进程版本相同，16.2）。
- 非 2xx 视为失败，错误信息包含状态码。

### 6.6.3 单次更新流程
1. 非远程配置直接返回。
2. GET 远程内容；`CheckConfig` 校验。
3. `lastUpdated` = 现在，更新记录。
4. 与旧内容相同则结束；否则写入新内容。
5. 若为选中配置且服务已连接，`ReloadService`。

手动更新入口：仪表配置卡更新按钮、配置选择行菜单“更新”，失败弹错误（动作名 “update remote profile”）。

## 6.7 远程配置导入链接
- 生成：`sing-box://import-remote-profile?url=<URL查询编码>#<名称>`（片段为名称，按 URL 片段规则编码）。
- 解析见第 4.8 节；名称为空时取远程 URL 的主机名。
- 导入流程：确认警告 → 仪表页 → “导入配置”表单（6.3）预填名称与 URL、类型远程。

## 6.8 分享与导出

| 菜单项 | 图标 | 行为 | 条件 |
|---|---|---|---|
| 保存文件 | square.and.arrow.down | 保存对话框，默认文件名 `<名称>.bpf`，内容为 `EncodeProfile` 结果 | 总是 |
| 分享文件 | doc | 生成 `%LOCALAPPDATA%\sing-box\Cache\share\<名称>.bpf` 后调用 Windows 分享界面 | 总是 |
| 保存 JSON 内容 | square.and.arrow.down | 保存对话框，默认 `<名称>.json`，内容为配置原文 | 总是 |
| 分享 JSON 内容文件 | curlybraces | 生成 `share\<名称>.json` 后调用 Windows 分享界面 | 总是 |
| 以二维码分享 URL | qrcode | 显示导入链接二维码（6.8.1） | 仅远程 |
| 以 QRS 码分享 | qrcode（行菜单中为 barcode） | 编码后显示动态 QRS（6.8.2）；编码失败动作名 “prepare QRS share” | 总是 |

- `.bpf` 编码内容：name、type（本地/iCloud 均编码为 LOCAL，远程为 REMOTE）、config；远程额外 remote_path、auto_update、auto_update_interval、last_updated（毫秒）。
- 导出失败动作名 “export profile”；分享失败 “share profile”。
- Windows 分享界面通过 `IDataTransferManagerInterop::ShowShareUIForWindow` 实现；不可用时退化为“在资源管理器中显示该文件”（待定 A-12）。

### 6.8.1 二维码
- 内容为 6.7 导入链接；前景色为文字色，背景透明；纠错级别 L。
- 仪表卡中以弹出框（popover）显示，最小 300×300；选择工作表中以工作表显示，最小 400×400。

### 6.8.2 QRS 动态码
- 工作表最小 400×520；QR 图 280×280，前景为文字色、背景白。
- 控件：“FPS”（−/值/+ 与滑块，1–60，默认 10）；“分片大小”（−/值/+ 与滑块，100–1500，步长 100，默认 500，变化后重新编码）；按钮“什么是 QRS”（打开 https://github.com/qifi-dev/qrs）与“关闭”。
- 编码：数据 = 文件头元数据包装（文件名 `<名称>.bpf`，类型 `application/octet-stream`）后，zlib（窗口 15，默认压缩级别）压缩，Luby Transform 喷泉码分片；每帧块二进制布局（小端）：`degree u32 | indices u32×degree | k u32 | bytes u32 | checksum u32 | data`，Base64 后加前缀 `https://qrss.netlify.app/#`。
- 帧缓冲 30 帧、图像 512 像素生成，纠错级别 L；k = ⌈数据长度/分片大小⌉，所需帧数 = max(⌊k×1.3⌋, k+5)（k=0 时为 1）。
- 实现必须与基线 LubyTransform 实现逐字节兼容（可被 qrss.netlify.app 与官方客户端扫描还原）。

## 6.9 扫码导入
- 工作表最小 500×400：摄像头预览 + 摄像头选择器（多个摄像头时）+ “取消”；识别到普通二维码：解析导入链接，失败动作名 “parse QR code profile link”，非导入链接提示“二维码不包含有效的配置导入链接。”；识别到 QRS 帧：显示进度百分比（最多 99%）与“QRS”标签，集齐后解包文件头并按 6.3.5 导入，失败动作名 “decode QRS profile data”。
- 摄像头访问被拒绝：警告“摄像头访问被拒绝 / 请在设置中允许摄像头访问以扫描二维码。”按钮“打开设置”（`ms-settings:privacy-webcam`）。
- 实现：Media Foundation 采集（`internal/platform/camera`）+ 纯 Go 二维码解码（gozxing）（待定 A-13）。
