# 04 主窗口与导航

## 4.1 主窗口结构

```
┌───────────────────────────────────────────────────────────────────────────┐
│ [远程控制▾] [00:12:34 ■]                      [仪表项⊞]        ─  □  ✕    │ ← 统一工具栏（高 52）
├──────────────┬────────────────────────────────────────────────────────────┤
│ ▣ 仪表        │  页面标题（大标题，随页面）                                 │
│ ▣ 组          │                                                            │
│ ▣ 连接        │                 详情列（NavigationStack）                   │
│ ▣ 日志        │                                                            │
│ ▣ 工具   (2)  │                                                            │
│ ▣ 设置        │                                                            │
└──────────────┴────────────────────────────────────────────────────────────┘
  侧边栏 150            详情 650（理想宽度），窗口最小高度 500
```

- 布局：两栏分栏（侧边栏 + 详情）。侧边栏理想宽 150，可在 130–220 之间拖动；详情理想宽 650；窗口最小高度 500，窗口尺寸由内容的最小/理想尺寸决定（对应 `windowResizability(.contentSize)`），默认 800×560。
- 其他窗口：配置内容编辑窗口默认 700×500（可多开，每个配置一个）；Tailscale SSH 终端窗口默认 880×560（每个会话一个）。
- 侧边栏不可滚动，列表样式为“侧边栏样式”：行高 28，图标 16，选中行背景为 accent @ 0.2 圆角 6（窗口非活动时为 secondary @ 0.15）。
- 侧边栏可折叠（工具栏左侧折叠按钮，对应 macOS 的侧边栏切换按钮），快捷键 Ctrl+Alt+S。
- 详情列为一个导航栈：页面标题即导航标题；进入子页面时标题左侧出现“‹”返回按钮；切换侧边栏项时清空导航栈。

## 4.2 导航项

| 页面 | 标题键 | 图标（SF Symbol） | 显示条件 |
|---|---|---|---|
| dashboard | Dashboard（仪表） | text.and.command.macwindow | 总是 |
| groups | Groups（组） | rectangle.3.group.fill | 服务严格已连接且当前配置有出站组 |
| connections | Connections（连接） | list.bullet.rectangle.portrait.fill | 服务严格已连接 |
| logs | Logs（日志） | list.bullet.rectangle | 总是 |
| tools | Tools（工具） | terminal.fill | 总是 |
| settings | Settings（设置） | gear.circle.fill | 总是 |

- 远程控制模式下，显示条件中的“服务”指远端服务。
- 工具项右侧徽标：`工具徽标数 + 失败的 Taildrop 发送会话数`，为 0 不显示。工具徽标数 = 未读崩溃报告 + 未读 OOM 报告 + 未读功耗报告 + Taildrop 待处理文件。
- 当前页变为不可见（如服务停止时位于“连接”页，或分组变空时位于“组”页），自动回到仪表。

## 4.3 工具栏

从左到右（导航区）：
1. **远程控制选择器**：当“存在已保存的远程服务器”或“当前处于远程控制”时显示。纯文字菜单按钮，文字为当前远程服务器显示名，或“本机”（Local Device）。菜单项见第 11.8 节。
2. **断开按钮**（处于远程控制时，替代启动/停止按钮）：内容为远程运行时长文本（RemoteUptimeText，与 RuntimeDurationText 同样式）+ 图标 antenna.radiowaves.left.and.right.slash；仅显示图标样式；点击退出远程控制，回到本机。
3. **启动/停止按钮**（StartStopButton，见 4.4）。

右侧（主区）：
4. **仪表项**（仅仪表页）：图标 square.grid.2x2，提示文字“仪表项”，打开卡片管理工作表（第 5.6 节）。
5. 各页面自有工具栏按钮（日志、连接页，见对应章节）追加在其后。

## 4.4 启动/停止按钮（StartStopButton）

- 结构：`HStack`：运行时长文本（仅严格已连接时显示）+ 图标按钮。
- 运行时长：caption、secondary、等宽数字；格式小于 1 小时为 `M:SS`，否则 `H:MM:SS`；起点来自 StartedService.`GetStartedAt`；每 1 秒刷新。
- 图标：未连接为 play.fill（提示“启动”），已连接/连接中为 stop.fill（提示“停止”）；图标切换使用弹簧动画（response 0.35，damping 0.75）。
- 禁用：无任何配置，或服务状态不可切换（connecting/disconnecting），或服务未安装。
- 点击启动：执行第 2.5 节流程；点击停止：`StopService`。
- 失败：弹出错误警告（第 14 章），动作名 “start service” / “stop service”。

## 4.5 窗口行为

- 关闭窗口（✕ 或 Ctrl+W）：仅隐藏窗口，应用继续在托盘运行（“将菜单栏保留在后台”关闭且托盘图标不显示时，关闭窗口即退出应用，见第 12 章）。
- Ctrl+Q：退出应用（不停止服务；核心由守护进程服务持续运行）。
- Ctrl+,：打开设置页。
- 窗口从隐藏变为可见时重新订阅数据；隐藏 3 秒后取消非必要订阅（第 2.7 节）。
- 应用单实例：第二个实例启动时把参数（深链接、.bpf 路径）转交第一个实例并激活其窗口（`App.RequestSingleInstanceLock` + `OnSecondInstance`）。

| 菜单 | 项目 | 快捷键 |
|---|---|---|
| sing-box | 关于 sing-box | — |
| | 设置 | Ctrl+, |
| | 隐藏 sing-box（隐藏全部窗口） | — |
| | 退出 sing-box | Ctrl+Q |
| 文件 | 关闭（关闭当前窗口） | Ctrl+W |
| 编辑 | 撤销 / 重做 / 剪切 / 复制 / 粘贴 / 全选 | Ctrl+Z / Ctrl+Y / Ctrl+X / Ctrl+C / Ctrl+V / Ctrl+A |
| 窗口 | 最小化 / 缩放 / 主窗口 | — |

- 托盘图标显示时，“退出 sing-box”与“关闭”为自定义实现：退出即彻底退出应用；关闭仅隐藏窗口。
- 菜单项不得超出上表（与基线一致，不增加“新建配置”等项）。

“关于”面板：应用图标、名称、版本（应用版本 + 核心版本）、版权、GPLv3 许可链接、源代码仓库链接（第 17 章）。

## 4.7 全局检查（窗口级）

窗口内以下事件统一以模态警告呈现（同一时刻只显示一个，后来者排队）：

1. **导入配置**（打开 .bpf 文件、拖放、深链接）：标题“导入配置”，内容“确定要导入配置 {名称} 吗？”，按钮“导入”/“取消”。确认后切到仪表页并导入。
2. **导入远程配置**（`sing-box://import-remote-profile`）：标题“导入远程配置”，内容“确定要导入远程配置 {名称} 吗？你将连接到 {主机} 下载配置。”，按钮“导入”/“取消”。确认后切到仪表页并打开“导入配置”工作表（内容为新建配置页，预填名称与 URL，类型为远程）。
3. **弃用警告**：服务变为已连接后，若偏好 `disable_deprecated_warnings` 为假，调用 `GetDeprecatedWarnings`，逐条显示：标题“弃用警告”，内容为说明；有迁移链接时按钮“文档”（打开链接）/“好”，否则仅“好”；两条之间间隔 300 ms。
4. **上次断开错误**：服务从 connecting 直接变为 disconnected 时，若存在启动失败信息（`ServiceStatus.FATAL` 的 `errorMessage`），弹出错误警告。
5. **远程控制错误**：远程连接失败、认证失败时弹出（第 11.8 节）。

macOS 特有检查（“应用位置错误/移动到应用程序”、“需要完全磁盘访问权限”、“安装辅助服务”、“需要辅助服务”、“WiFi 状态访问”）在 Windows 上的处理见第 15 章。

## 4.8 深链接与文件打开

| 输入 | 处理 |
|---|---|
| `sing-box://import-remote-profile?url=<URL编码的远程地址>#<名称>` | 解析：`url` 参数为远程地址；片段为名称，为空时取远程地址的主机名；进入 4.7 第 2 项 |
| `sing-box://taildrop?endpoint=<端点标签>` | 设置待处理 Taildrop 端点，切到工具页并打开该端点的 Taildrop 页 |
| 以 `.bpf` 结尾的文件路径或 `file://` URL | 读取并解码（ApplicationService.`DecodeProfile`），进入 4.7 第 1 项；失败弹出错误，动作名 “import profile from URL” |
| 其他 | 错误警告：“已处理未知 URL {url}” |

- 动作（action）判定：URL 有主机名则取主机名；否则取 `scheme:` 之后的部分，去掉查询、片段与前导 `/`。
- 查询参数取值：优先标准解析；失败时按 `&`/`=` 手动拆分并做百分号解码。
- 注册：安装器在 HKLM 写入 `sing-box` 协议与 `.bpf` 关联（`mygo.json` 的 `urlSchemes: ["sing-box"]`、`fileAssociations: [{ext:["bpf"], name:"sing-box Profile"}]`）；开发运行（`scripts/dev/install.ps1` 安装到开发目录）时调用 `App.RegisterURLScheme("sing-box")` 注册到 HKCU。
- 处理器在 `App.Run` 之前通过 `App.OnOpenURL`、`App.OnOpenFile` 注册，并在 `OnSecondInstance` 中处理参数，确保冷启动与热启动都能收到。
- 窗口隐藏时收到深链接：先显示并激活主窗口再弹出警告。
