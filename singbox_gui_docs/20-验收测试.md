# 20 验收测试

## 20.1 测试环境
- Windows 11 24H2 x64（主）、Windows 10 1809/22H2 x64、Windows 11 24H2 arm64；100%、150%、200% 缩放；浅色/深色；中文（简体）、English、فارسی。
- 对照组：同版本 macOS 客户端（16.1 锁定提交）运行于 macOS 26，具体完整版本、构建号及显示条件固定于 3.9 的截图清单，使用相同配置文件；不得混用 macOS 15 的截图。
- 测试配置集 `testdata/profiles/`：最小直连、含 selector/urltest 分组（≥ 3 组、每组 ≥ 20 出站）、含 tun + 系统代理、含 Tailscale 端点、含弃用字段、语法错误、远程配置服务器（本地 HTTP 服务，可返回 200/304/404/延迟）。
- 自动化：`internal/testutil` 假守护进程做单元/组件测试；端到端使用真实已签名安装包 + MyGo automation 插件，在有交互式登录会话的实机或虚拟机上运行（22.7）。
- 账户：一个管理员账户、两个标准用户账户（用于所有权与 UAC 用例）；测试机未导入本项目证书；测试机保持 SmartScreen 与 Microsoft Defender 默认开启，安装包从发布页经浏览器下载（带网络标记）。

### 安全与认证（TC-SEC）
| 编号 | 步骤 | 期望 |
|---|---|---|
| SEC-01 | 普通用户尝试替换安装目录中的任何文件、写入守护进程数据目录 | 拒绝访问 |
| SEC-02 | 普通用户直接连接 `\\.\pipe\ProtectedPrefix\Administrators\sing-box` 并调用 RPC | 守护进程拒绝（客户端不是守护进程本身，事件日志记录） |
| SEC-03 | 将 `sing-box.exe` 复制到用户目录运行 | E-DAEMON-09；worker 无法通过父进程检查 |
| SEC-04 | 由另一个程序（非 `sing-box.exe`）以 worker 参数启动 `sing-box-daemon.exe worker …` | worker 拒绝并退出 |
| SEC-05 | 由 `sing-box.exe` 启动的 `sing-box.exe` 再拉起 worker | 被拒绝（父进程的父进程不能是 sing-box.exe）；正常启动路径（资源管理器、Run 项、安装器以用户身份启动、`--updated` 重启）均可连接 |
| SEC-06 | 另一会话的用户连接本用户 worker 管道 | 被拒绝（worker 管道 DACL 仅 SYSTEM、Administrators、本用户，且只接受 GUI 进程 PID） |
| SEC-07 | 从另一台计算机访问守护进程管道 | 被拒绝 |
| SEC-08 | 管理员开启非网络特权模式（11.3）后关闭 | UAC 执行 `service set-insecure-mode true`；关闭经 DesktopService，无 UAC；状态与守护进程设置一致 |

## 20.4 外观一致性验收
- 对照截图：每个页面与工作表在相同窗口尺寸（主窗口默认尺寸）、浅/深色、英文与简体中文下，各截取一张 Windows 与对照组截图，按 16.3 模块命名存入 `testdata/screenshots/<版本>/`。
- 判定：布局结构（元素集合、顺序、分组、对齐）完全一致；文案一致（附录 B）；颜色差 ΔE ≤ 3（强调色与语义色）；尺寸偏差 ≤ 2 DIP；字体为第 3 章规定的替代字体。
- 允许差异仅限 3.9、第 15 章与附录 A 中已决定的项；每项差异记录原因和截图位置。正文区域不默认使用 Windows Mica/Acrylic；按锁定 macOS 26 清单对比，不能混用系统版本。
- 每次上游同步（16.4）重新执行。

## 20.5 自签名实机验证（SIG，M0 闸门）
在真实 Windows 上执行：Windows 10 1809/22H2 x64、Windows 11 24H2 x64/arm64，各系统/架构组合一台，非开发机，未安装本项目证书，Defender 与 SmartScreen 默认开启，以普通交互式会话登录。测试文件由 CI 产出（正式证书或与正式证书同规格的测试证书），变体由 `scripts/sign/make-variants.ps1` 生成。每个用例记录 Windows 版本、结果、守护进程事件日志与 worker stderr。

| 编号 | 步骤 | 期望 |
|---|---|---|
| SIG-01 | 安装同一自签名证书签名的 GUI、守护进程、安装包；启动 GUI 并连接测试配置 | 服务安装并运行；worker 输出 `READY`；`GetDaemonInfo` 成功；连接成功 |
| SIG-02 | 管理员把 `sing-box.exe` 换成**未签名**的同一构建 | worker 拒绝（无签名）；GUI 显示 E-DAEMON-05 或 E-DAEMON-02；无法连接 |
| SIG-03 | 换成**另一张同规格自签名证书**签名的 `sing-box.exe`（主题相同） | 被拒绝（签名证书不同）；E-DAEMON-05 |
| SIG-04 | GUI 与守护进程都用**已过期**的自签名证书签名（`NotAfter` 在过去） | 服务无法启动（守护进程验证自身失败）；E-DAEMON-06 |
| SIG-05 | 修改已签名 `sing-box.exe` 的 1 个字节（签名范围内） | 被拒绝（摘要不符）；GUI 自检报 E-DAEMON-05 |
| SIG-06 | 证书 `NotBefore` 在未来（或把系统时间调到 NotBefore 之前） | 被拒绝；E-DAEMON-06“系统时间不正确” |
| SIG-07 | 已安装版本 N，运行由同一证书签名的版本 N+1 的 `InstallUpdate` | 返回 `STARTED`；无 UAC；更新后连接正常 |
| SIG-08 | 已安装版本 N，版本 N+1 由**新证书**签名（轮换演练） | `InstallUpdate` 返回 `SIGNER_MISMATCH`；更新器改走 UAC；安装后新 GUI 与新守护进程连接正常 |

- 附加观察（记录但不作通过条件）：SIG-01 时 SmartScreen 与 UAC 的表现（21.4）；无 EKU 证书、SHA-1 签名证书、RSA 2048 证书的结果（用于确认 21.1.2 的余量）。
- 任一 SIG 用例在任一系统上不符合期望 → M0 闸门不通过，按 A-29 记录证据并报告，不自动启用附录 C。
- 每个发布候选（含补丁版、GUI 修订版及测试版）均执行下述 20.7 闸门。M0、证书轮换、认证/安装布局变更时另执行完整 SIG-01～SIG-08；不能以“接口没变”豁免。
- SIG-07 的“同证书且核心版本递增”前提不成立时，必须测试实际适用路径：GUI 修订版执行 UPD-03b，证书轮换执行 UPD-06；未执行的路径记录不适用原因。

## 20.7 每个发布候选的真实 Windows 闸门
- 环境：Windows 10 1809/22H2 x64、Windows 11 24H2 x64/arm64，有交互式登录会话，使用真实服务与正式签名候选包。最低支持系统按 A-11 在 M0 及每个候选验证；不能用纯假服务或只有交叉编译的结果代替运行测试。
- 全新安装、worker 认证连接、启动/停止/重载、TUN 路由与 DNS、系统代理开启/恢复、退出 GUI 后连接保持、再次打开 GUI 恢复状态必须通过。
- 从上一公开支持版本升级到候选：验证适用的 InstallUpdate 或 UAC 路径、配置及偏好保留、以登录用户身份重启、恢复连接；GUI 修订与证书轮换使用 20.5 对应路径。首次发布须构建明确标记的测试前序包验证升级链路，不能捏造历史正式版。
- 发布证据 `validation.json` 至少记录候选标签、源提交、工作流 run ID、SHA256SUMS 摘要、各架构安装包 SHA-256、系统/架构、执行身份、用例、结果、日志位置、执行时间和验证人/运行器标识；不适用项必须说明前提。失败、缺失、哈希不匹配均禁止公开发布。
- 证据必须对应最终分发字节。测试后重编译、重新签名或替换资产均使旧证据失效。操作方式与晋级流程见 22.4。
