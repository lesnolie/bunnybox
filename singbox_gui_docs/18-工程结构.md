## 18.2 依赖方向
- `ui/*` → `core`、`store`、`profile`、`ondemand`、`update`、`remote`、`rpc/client`；`ui` 包之间仅依赖 `ui/common`。
- `core` → `rpc/client`、`store`；不依赖 `ui`。
- `platform/windows` 为叶子包，仅由非 UI 包调用；UI 需要平台能力时经上层服务。
- GUI 模块禁止导入 `github.com/sagernet/sing-box` Go 模块（2.4）；与守护进程之间只通过 proto 生成代码共享类型。仓库中不包含任何守护进程或核心的修改代码。

## 18.3 状态与线程
- 全局 `AppState`（当前配置、服务状态、所有权、远程模式、偏好快照）位于 `internal/app`，变更经事件总线通知；UI 只在 UI 线程读写视图状态，后台 goroutine 通过 MyGo 的 UI 调度函数投递更新（2.7）。

## 18.4 构建
- 开发：
  1. `scripts/sign/New-SelfSignedCert.ps1 -Out build\dev-cert`（一次性，生成开发者自己的证书，21.5）。
  2. `scripts/daemon/build.ps1 -Arch amd64` 构建守护进程；`mygo build -skip-installer` 构建 GUI（输出名 `sing-box.exe`）。
  3. `scripts/sign/sign.ps1 -Pfx build\dev-cert\codesign.pfx` 签名 GUI、守护进程。
  4. `scripts/dev/install.ps1`（管理员）：把产物复制到 `%ProgramFiles%\sing-box-dev\`（布局同 2.6），设置 ACL，执行 `service install`，写入布局注册表键。守护进程只接受安装布局中的 GUI，因此不能直接从构建目录运行 GUI 与守护进程通信（E-DAEMON-09）。
  - 界面开发可用 `--fake-daemon` 启动参数（仅开发构建编译）连接 `internal/testutil` 的假守护进程，不需要安装服务。
- 发布：由 GitHub Actions 完成（第 22 章）。顺序：build_boxdd 构建守护进程 → `mygo build -skip-installer` → 签名 GUI 与守护进程 → 暂存到 `resources\daemon` → NSIS 打包 → 签名安装包 → 校验三者签名者一致 → `SHA256SUMS` + `SHA256SUMS.sig`。
- 链接与打包规则（降低杀毒软件误报，21.4）：不使用 UPX 等加壳/压缩；GUI 嵌入版本资源（CompanyName、ProductName、FileDescription、FileVersion、OriginalFilename=`sing-box.exe`）与应用清单（`asInvoker`）；守护进程的版本资源由上游构建决定，不修改；可执行文件名在各版本间保持不变。
- 架构：windows/amd64、windows/arm64；目标最低 Windows 10 1809（x64），Windows 11 支持 x64/arm64；完整依赖兼容性须在 M0 实测，不以单一组件最低版本推定整包支持。

## 18.5 代码规范
- `gofmt`、`go vet`、`staticcheck` 必须通过；公开函数写注释。
- 所有用户可见字符串只能来自 `locales`；CI 检查 UI 包中不得出现硬编码英文/中文（日志与错误动作名除外，14.1）。
- 偏好键只在 `store/prefs.go` 定义一次（13.3），其余位置使用类型化访问器。
