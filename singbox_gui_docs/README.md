# sing-box Windows 图形客户端 开发文档

本文档集描述一个以 Go 编写、运行于 Windows 10/11 的 sing-box 图形客户端（下称“本应用”）。本应用在功能、页面结构、交互与视觉上与 sing-box 官方 macOS 客户端（SFM，及其共用代码的 iOS 客户端 SFI）保持一致，并持续跟随其版本更新。

文档面向实现本应用的开发者（含 AI 编码代理）。所有章节均为规范性描述：凡写明“必须”的条目为验收依据；标注“可选”的条目为改进项，默认不实现；尚未定论的事项统一列于《附录A 待定事项》，并给出推荐默认值，开发时按推荐默认值执行。

## 一句话目标

功能与官方 macOS 客户端一致，界面与其一致；平台差异按第 15 章映射；与上游保持版本同步（第 16 章）。

## 开发交接约束（先读）

- 前端采用 MyGo 原生 UI；应用自身页面、表单、弹窗与托盘弹出窗口以锁定的官方 macOS 客户端为视觉与交互基线。外部网页登录认证可使用 WebView2，不把主界面改成 Web 前端。
- 后端采用官方 sing-box 核心与 boxdd 守护进程的**未修改源码**，按锁定标签使用官方脚本构建，再由本项目签名。它不是官方签名的二进制发布包；不得宣称本应用是官方客户端。
- 不自行重写核心服务、不维护后端补丁。MyGo 只负责界面与应用层逻辑；服务、核心运行和特权能力由官方后端提供。
- 上游核心更新：自动发现、检查差异、构建候选；每个候选通过真实 Windows 安装、连接、升级验证后才公开发布。界面更新单独对照 Apple 客户端移植，核心版本更新不代表界面同步完成。
- 当前仓库是开发规范，不是已运行的实现。版本、路径、接口和 MyGo API 必须在 M0 对锁定源码复核；文档中的脚本名与工作流属于待实现契约，不代表文件已经存在。不得把源码推断或假服务测试写成实机验证通过。
- M0 优先验证官方后端连接闭环；M1 优先验收仪表盘、设置表单、弹出菜单三个视觉样板。缺少 macOS 截图时可继续骨架工作，但不得宣布视觉验收通过。
- 附录 C 仅为历史备选，不属于当前授权范围；遇到后端不可兼容问题应保留证据并报告，不能自行切换为修改后端方案。

## 阅读顺序建议

1. 先读 01、02、15、21，理解架构、平台差异、签名与分发方式；
2. 再读 03、04，确定视觉与外框；
3. 按 05–12 逐页实现；
4. 13、14 贯穿实现全过程；
5. 16、22 在每次上游发版时执行（22 为候选构建、验证与晋级流程）；
6. 19、20 用于排期与验收；遇到不确定处查附录A。
