# 12 托盘、开机启动、应用更新、通知

## 12.1 托盘图标
- 使用 MyGo `NewTray`。“在托盘中显示”（`show_menu_bar_extra`）关闭时销毁托盘图标，开启时创建。
- 图标：应用单色托盘图形（与基线 MenuIcon 同形），按 `Tray.Dark()` 选择白/黑两套，`OnAppearanceChange` 时重绘。尺寸 16×16 DIP，提供 1×/1.5×/2× 位图。
- 已连接（`isConnectedStrict`）显示完整图形；未连接在图形上叠加左上→右下的斜线：线宽 max(1.5, 高×0.09)，圆头，先以 2 倍线宽挖空再描线（与基线一致）。
- 实时速率（`menu_bar_extra_speed_mode_1`）：
  - Windows 通知区无法在图标旁显示文字，速率按以下方式显示：
    - 托盘提示（ToolTip）每秒更新：已启用 `sing-box\n↑ <上行>/s\n↓ <下行>/s`；统一 `sing-box\n<上行+下行>/s`；已禁用 `sing-box`。
    - 托盘弹出菜单头部（12.2）在开关下方显示同样的速率文字（caption，等宽数字）。
  - 速率来自 `SubscribeStatus`（FormatBytes）；服务未连接时不显示速率。
  - （可选）“任务栏速率浮窗”：不实现，见附录A A-17。
- 单击（左键）与右键均打开托盘弹出菜单；双击打开主窗口。

## 12.2 托盘弹出菜单
采用自绘弹出窗口（无边框、置顶、失焦即关闭、按第 3 章复刻 macOS 的圆角与 MyGo 自绘材质，宽 250 DIP，出现在托盘图标上方并贴靠工作区边缘），以便承载开关控件；子菜单以同风格级联弹出。结构自上而下：

1. **头部**（高 36）：左侧“sing-box”（粗体 13，左距 14）；右侧开关（右距 14），开关切换启动/停止当前配置；服务处于 connecting/disconnecting 时开关位置显示小号旋转指示器。失败弹出“错误”对话框（按钮“好”）。已连接时下方显示速率行（12.1）。
2. **分组 ›**（仅服务已连接且存在可选择分组时出现）。子菜单：
   - 第一项“URL 测试”（自定义项，宽 250 高 22，菜单字体，悬停高亮；测试中显示小旋转并禁用）：对所有分组执行 URL 测试。
   - “关闭所有连接”。
   - 分隔线后每个可选择分组一个子菜单（标题为分组标签）：首项“URL 测试”（仅测此组），其后为出站列表：单选勾选当前选择，文字为“标签 + 制表位右对齐的延迟 `<n>ms`”（无延迟不显示），延迟着色同第 7 章；点击调用 `SelectOutbound`。
   - 结构（分组顺序、各组出站顺序）不变时只更新勾选与延迟，否则重建。
3. **配置 ›**：所有配置文件，单选勾选当前选中；无配置时禁用项“无配置文件”。选中项不存在时自动选第一个并保存。点击切换选中配置（服务运行时按第 6 章“切换配置即重载”处理）。
4. 分隔线。
5. **远程控制**分节（存在已保存服务器时，同第 4 章选择器菜单）。
6. **打开**：显示并激活主窗口。
7. **退出**：退出应用（不停止服务，与基线一致）。

## 12.3 窗口关闭与后台
- 关闭主窗口：隐藏窗口。若“保持托盘在后台”关闭且没有其他可见主窗口，则退出应用；开启时应用留在托盘（MyGo：在 `OnClose` 中隐藏，区分退出触发的关闭）。
- 单实例：第二次启动时把命令行（含 `sing-box://` 链接、文件路径）转发给已运行实例并退出；已运行实例显示主窗口。

## 12.4 开机启动
- 使用 `mygo.App.SetOpenAtLogin(bool)` / `OpenAtLogin()`（Windows 为当前用户 Run 项）。GUI 以普通权限启动，经 worker 连接已在运行的守护进程，无 UAC 提示。由 Run 项启动时父进程为资源管理器，满足 2.3.2 的进程形态约束。
- 守护进程服务本身为自动启动服务，开机即运行但不自动连接；连接由登录后的 GUI 按下述规则发起（与基线由应用发起连接一致）。
- 启动时 `App.WasOpenedAtLogin()` 为真（或带 `--login`）：
  - 若“在托盘中显示”与“保持托盘在后台”均开启，则不显示主窗口；否则显示。
  - 若 `started_by_user` 为真，自动启动当前选中配置（失败时发出系统通知，不弹模态框）。
- 启动时总是：启动远程配置自动更新调度（第 6 章）、按需启动评估器（15.4）、恢复远程控制会话（11.8）。

## 12.5 应用更新

更新的来源与完整性由“发布签名的校验和文件”保证（21.3）：每个发布附带 `SHA256SUMS` 与其 Ed25519 签名 `SHA256SUMS.sig`，公钥编译进 GUI。Authenticode 自签名只用于满足守护进程的同签名者要求，不作为更新可信依据。

**来源与检查**
- 由本项目 `internal/update` 实现（不使用 MyGo `Updater` 的检查/安装：MyGo 的更新器要求应用目录可写，否则 `Check` 直接返回“更新已禁用”；本应用安装在受保护的 `Program Files` 目录，二者不兼容）。
- 请求本应用发布仓库（A-10）的 GitHub Releases API：稳定版通道取 `/releases/latest`；测试版通道取 `/releases?per_page=30` 中版本最高的发布（含预发布）。有 GitHub 令牌（11.2“GitHub 令牌”，凭据管理器）时携带 `Authorization: Bearer <令牌>`。发布由第 22 章的工作流自动产生。
- 版本号规则见 16.2：`<核心版本>` 或 `<核心版本>+w<N>`（同一核心版本上的 GUI 修订）。比较时先按语义化版本比较核心版本部分，相同时比较修订号 N（无修订视为 0）。结果缓存于 `cached_update_info`（JSON：版本、发布说明、发布页 URL、安装包名与大小、是否预发布）。缓存仅在“属于当前通道且版本较新（或当前为预发布而通道为稳定版）”时保留。
- 首次启动（`update_check_prompted` 为假）弹出“检查更新 / 是否启用从 **GitHub** 自动检查更新？”按钮“好”（开启并立即检查）/“不，谢谢”。
- 已开启自动检查：启动时先加载缓存（若该版本未展示过则展示更新工作表），再后台检查（仅在启动时检查，与基线一致；可选：长时间运行时每 24 小时再检查，默认不实现，A-18）。自动检查失败静默；手动检查失败弹出错误（动作名 “check for update”）。
- 同一版本只自动展示一次（`last_shown_update_version`）。
- 从源码构建且未编译进更新公钥的版本：设置中“自动检查更新”仍可用，但“更新”按钮改为打开发布页（不自动安装）。源码构建使用构建者自己的证书签名，与官方发布的签名者不同，不能用官方安装包原地升级（21.5）。

**更新工作表**（最小宽 480，内边距 20，间距 16）
- 标题“检查更新”（headline）；副标题“有新版本可用：<版本>”（subheadline 次要）。
- 发布说明：Markdown 渲染（GitHub 风格，字号 10，可选择文本，`:shortcode:` 转 emoji），最大高 300 滚动。
- 下载中显示确定进度条；安装中显示不确定进度条。
- 按钮行：“查看发布”（有发布页时，左侧）……“取消”（Esc，下载中禁用）、“更新”（默认按钮，下载中禁用）。下载中不可关闭。

**下载与校验**（任一步失败均删除已下载文件并弹出错误，动作名 “install update”）
1. 下载发布资产 `SHA256SUMS` 与 `SHA256SUMS.sig`，以编译进的公钥验证 Ed25519 签名（签名对象为 `SHA256SUMS` 文件内容的 SHA-256 摘要，与 MyGo 更新清单同一方案）。失败 → E-UPD-01“更新签名无效”。
2. 选择资产 `sing-box-<版本>-windows-<arch>-setup.exe`（arch：`amd64`、`arm64`，与当前安装的架构相同）。资产名必须出现在 `SHA256SUMS` 中。
3. 下载到 `%LOCALAPPDATA%\sing-box\Cache\updates\`，先写 `.part` 临时文件，计算 SHA-256 与清单一致、文件大小与发布资产一致后重命名。不一致 → E-UPD-02“更新文件校验失败”。

**安装（与 sing-box-for-desktop 相同的两条路径）**
1. **守护进程安装（首选，无 UAC）**：守护进程可用时调用 DesktopService.`InstallUpdate(installer_path)`。守护进程会校验：安装包是 NSIS 安装程序；版本资源 `ProductName` 为 `sing-box`；Authenticode 签名证书与守护进程相同；版本资源 `FileVersion` 按语义化版本严格新于守护进程自身的核心版本。通过后守护进程以 SYSTEM 身份在调用者会话中启动 `<安装包> --updated --force-run`，返回 `STARTED`，GUI 立即退出。
   - 返回 `SIGNER_MISMATCH`（证书已轮换，21.1.4）或 `NOT_NEWER`（同一核心版本上的 GUI 修订 `+w<N>`）或调用报错（守护进程不可用、安装包 `ProductName` 不是 `sing-box`）→ 自动改走第 2 条路径，不向用户报错。
2. **UAC 安装（回退）**：以 `ShellExecuteExW`（verb `runas`）运行安装包，参数 `--updated --force-run`。UAC 对话框显示“未知发布者”（21.4）。用户取消（错误 1223）→ 恢复工作表，不报错；启动失败 → 错误“无法启动更新安装程序”。启动成功后 GUI 立即退出。
- 两条路径共用同一个安装包。安装包在 `--updated` 模式下：跳过所有页面 → 等待并结束运行中的 `sing-box.exe` → 停止服务 → 替换文件 → 以安装目录中的新守护进程执行 `service install --working-directory <原守护进程数据目录>`（更新服务配置、重设 ACL、启动服务）→ 在 `--force-run` 时以**会话的登录用户身份**（非 SYSTEM，非提权）启动 `sing-box.exe --updated`。以用户身份启动是 2.3.2 进程形态约束的要求。
- GUI 以 `--updated` 启动时：若 `started_by_user` 为真则自动连接；不显示主窗口以外的提示。
- 产品名决定：安装包版本资源的 `ProductName` 由构建常量 `installerProductName` 决定。取 `sing-box` 时第 1 条路径可用；若名称许可（A-10）不允许使用该值，则取本应用名称，此时更新始终走第 2 条路径（功能相同，多一次 UAC 确认）。推荐默认见 A-10。

## 12.5.1 证书过期时的恢复
自签名证书过期后守护进程拒绝启动与连接（21.1.3），但更新检查、下载、校验与 UAC 安装都不依赖守护进程，因此用户仍可通过“检查更新”安装由新证书签名的版本。仪表盘在 E-DAEMON-06 时直接提供“检查更新”入口（第 5 章）。

## 12.6 系统通知
- 使用 MyGo Notifications。来源：StartedService.`SubscribeNotifications`（核心通知，如订阅更新、规则集错误等）、Taildrop 接收完成、远程配置更新失败、开机自动连接失败。
- 核心通知带 URL 时提供两个动作按钮：“复制 URL”、“打开”；点击通知主体等同“打开”（默认浏览器）。
- Taildrop 通知点击：显示主窗口并打开对应端点的 Taildrop 页（第 10 章）。
- 应用在前台时通知仍以横幅显示（与基线一致）。
