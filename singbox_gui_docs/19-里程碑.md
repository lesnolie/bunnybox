# 19 里程碑

每个里程碑结束时：对应验收用例（第 20 章）通过、可安装包产出、文档与实现一致。时长为单人全职估算。

| 里程碑 | 内容 | 交付与退出条件 | 估时 |
|---|---|---|---|
| M0 基础设施与签名验证 | 仓库骨架（18 章）、子模块与 `upstream.lock`、proto 生成、build_boxdd 构建脚本、自签名证书脚本与签名脚本（21.1、21.2）、NSIS 安装/卸载与服务注册（15.2.2）、worker 拉起与连接（2.3.1）、发布与上游工作流骨架（第 22 章）、i18n 生成脚本、假守护进程 | **闸门**：在真实 Windows（Windows 10 1809/22H2 x64 与 Windows 11 24H2 x64/arm64，各系统/架构组合一台，非开发机、未安装证书）上 SIG-01～SIG-08 全部通过（20.5）。未通过则记录证据、排查证书与前端集成；仍不可行时报告阻塞，不自行改后端（A-29）。另需：MyGo 进程形态核查（A-35）通过；CI 绿；工作流可产出已签名的草稿发布 | 2 周 |

## 19.1 依赖关系
M0（含签名闸门）→ M1 → M2 →（M3 ∥ M4）→ M5 →（M6 ∥ M7）→ M8。

## 19.2 风险
| 风险 | 影响 | 缓解 |
|---|---|---|
| 未获名称同意（17.2） | 公开发布受阻，报告负责人，不自行改后端 | M0 前联系作者，确定产品名与技术标识（A-10、A-29） |
| 官方守护进程不接受自签名证书（WinVerifyTrust 在某些系统配置下返回非预期错误码） | 整个架构不可用 | M0 签名闸门（20.5）；失败时按 A-29 报告阻塞 |
| 上游修改守护进程的签名者检查、布局或 worker 协议 | 新版本无法自动发布或无法连接 | 22.2 完整协议与行为差异检查阻止未经适配的晋级并开议题；16.3 监视 `experimental/boxdd/**` |
| 自签名证书过期 | 所有安装的应用无法连接，直到更新 | 证书有效期 10 年；`cert-expiry.yml` 提前 18 个月开议题；过期前至少 12 个月启动轮换（21.1.4）；UAC 更新路径不依赖守护进程（12.5.1） |
| 签名私钥泄露 | 攻击者可签名能被本产品守护进程接受的程序（需管理员权限才能放入安装目录） | 私钥只存 GitHub Actions 机密与离线备份；泄露即轮换（21.1.4） |
| 自签名分发导致 SmartScreen 警告与杀毒软件误报 | 下载转化率、用户信任；误报可能隔离守护进程导致无法连接 | 21.4 的 README 指引与哈希；不加壳、稳定文件名与版本资源；每个发布提交主要厂商误报申诉；后续可选商业证书（21.6，A-25） |
| 与官方客户端互斥 | 用户需在两者间选择 | 安装器明确检测与提示（15.10） |
| 更新私钥泄露或丢失 | 恶意更新 / 无法推送更新 | 私钥只存 CI 机密与离线备份；轮换流程（21.3.3，A-28） |
| MyGo 原生控件与 SwiftUI 外观差异 | “长得一样”验收 | M1 先做组件库与截图对比，偏差列入附录 A |
| VBoxUSB 驱动签名 | USB/IP 本机提供 | 驱动由 build_boxdd 暂存，随守护进程分发；无法加载时隐藏“+”（A-14） |
| 上游在开发期间发布新版本 | 返工 | 每个里程碑结束执行一次 16.4 同步，开发期间不追随 main |
