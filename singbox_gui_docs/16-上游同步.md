# 16 上游同步

本产品以 macOS 客户端为界面与功能基线，以 sing-box 核心为运行时。核心与界面分开跟踪：产品版本以核心版本为基底，界面基线以已移植、已验收的 Apple 提交为准。不得因核心升级而虚增 Apple 对齐版本。

## 16.1 锁定基线

文件 `upstream.lock`（仓库根目录，TOML）记录当前基线，CI 校验其与构建产物一致：

```toml
[apple_client]               # SFM/SFI 源码仓库 sing-box-for-apple
commit = "2dd154e7586188d5fff8de615e8c821ed25ec089"
version = "1.14.4"

[core]                       # sing-box
tag = "v1.14.4"
commit = "c005f35300ce76427dc285481ec5695f5b179cd2"

[desktop_reference]          # 官方桌面客户端 sing-box-for-desktop（仅作 Windows 行为参考）
commit = "8aab8eab022366e1032e952d499c9252b833e6c3"

[mygo]
commit = "1f039303abe1bf8b8f6a94ae15c4d6c5ff5d739f"
go = "1.27.3"
```

- 核心以 git 子模块 `third_party/sing-box` 固定在 `core.commit`（即 `core.tag` 指向的提交）。守护进程由该子模块原样构建，不修改任何源码：在子模块目录执行 `go run ./cmd/internal/build_boxdd -target=windows/<arch> -output=<暂存目录>\sing-box-daemon.exe`。该脚本从 git 标签读取版本号，按核心发布的默认构建标签与链接参数构建 `./experimental/boxdd`，并把 WinDivert 与 USB/IP 驱动文件暂存到输出目录；`libcronet.dll` 取自核心 go.mod 锁定的 `github.com/sagernet/cronet-go/lib/windows_<arch>` 模块目录（与 sing-box-for-desktop 的打包脚本相同）。构建工具链为核心 go.mod 要求的 Go 版本（`GOTOOLCHAIN=local`）。
- 协议集合的单一来源为待实现的 `scripts/proto/manifest.json`：入口包含 `daemon/*.proto` 与 `experimental/boxdd/desktop_service.proto`，解析其全部递归 `import`（含固定版本的 Google well-known types）。新增、删除、移动及依赖变化均须纳入检查。代码生成、差异检测和 CI 使用同一清单与解析器，不能各自维护不同通配符。
- `protoc` 及 Go 生成器固定版本。通过生成参数映射 `go_package` 到本项目生成包，尤其桌面协议上游包为 `main`，不得为改包名修改上游 proto。记录生成命令、依赖摘要和描述符集；GUI 不因此导入 sing-box 运行时代码。
- 构建前核验 tag 指向 commit、子模块工作树无修改、工具链可用；构建后复查源代码无补丁。签名只处理输出产物。
- Apple 客户端以只读子模块 `third_party/sing-box-for-apple` 固定在 `apple_client.commit`，仅用于比对与提取文案，不参与构建。
- sing-box-for-desktop 不作为子模块，只在 `desktop_reference.commit` 记录行为参考版本（安装器、worker、修复、更新流程）。

## 16.2 版本锁步
- 产品版本号 = 核心版本号（如 `1.14.4`），守护进程由同一核心标签构建，二者版本相同。
- 同一核心版本上的 GUI 修订：版本号写作 `1.14.4+w.1`、`1.14.4+w.2`（语义化版本的构建元数据，Git 标签 `v1.14.4+w.1`）。自有更新器按 12.5 的规则比较（先核心版本，再修订号）。
  - 安装包与 `sing-box.exe` 的版本资源：字符串表中的 `FileVersion` 写核心版本原文（`1.14.4`、`1.15.0-beta.3`，必须是合法语义化版本，不带 `+w.N`）；`ProductVersion` 字符串写完整产品版本（`1.14.4+w.1`）；数字版本（VS_FIXEDFILEINFO）写 `1.14.4.N`，预发布时为 `<主>.<次>.<修订>.0`。守护进程 `InstallUpdate` 读取字符串 `FileVersion` 并要求它严格新于自身核心版本，修订版因此返回 `NOT_NEWER`，更新器自动改用 UAC 路径（12.5）。
  - 不使用 `1.14.4-w.1` 这类预发布后缀：按语义化版本它低于 `1.14.4`。
- 核心预发布标签（`-alpha.N`/`-beta.N`/`-rc.N`）对应本产品测试通道，发布为 GitHub prerelease，版本号与标签一致。
- 守护进程与 GUI 必须同版本发布、同安装包分发；版本不一致视为需要修复（2.4.1）。
- 发布按第 22 章执行：自动准备候选，真实 Windows 验证通过后发布。

## 16.4 差异比对流程
每当上游发布新标签（核心 `v*` 与 Apple 客户端对应提交）时执行：

0. **触发**：由第 22 章的“上游核心”与“上游 Apple 客户端”工作流自动发现新版本并开出议题，议题附带下述差异报告；以下步骤由负责人在议题中执行。
1. **获取**：`scripts/sync/fetch.sh <core-tag>`：更新两个子模块到新版本对应提交（Apple 客户端选取明确的发布标签或待移植提交并记录依据，不以“同一天”推定兼容；核心单独升级时保留原 Apple 子模块及锁定项），不修改 `upstream.lock`。
2. **生成差异**：`scripts/sync/diff.sh`：
   - `git diff <旧>..<新> --stat -- ApplicationLibrary MacLibrary Library Localizable.xcstrings` 输出到 `sync/<版本>/apple.diffstat`；
   - 对 16.3 表每一行生成按模块分组的差异文件 `sync/<版本>/apple/<模块>.diff`；
   - 核心监视文件差异 `sync/<版本>/core.diff`；
   - 文案差异：比较新旧 `Localizable.xcstrings` 的 key 集与 en/zh-Hans/zh-Hant/ru/fa 值，输出 `strings-added/removed/changed.csv`。
3. **分类**：每个差异块标为：UI 布局 / 新功能 / 行为修正 / 文案 / 平台专有（忽略）/ 核心接口。记录到 `sync/<版本>/TRIAGE.md`（模板：差异文件、分类、影响章节、Windows 处理、负责人、状态）。
4. **更新文档**：受影响章节（本开发文档）先修改，再改代码；附录 B 由文案差异自动再生成后人工校对。
5. **实现**：按 TRIAGE 逐项提交，提交信息前缀 `sync(<版本>):`。
6. **验证**：运行第 20 章验收清单中受影响的用例 + 全部冒烟用例；截图对比（20.4）与 macOS 新版并排检查。
7. **锁定**：更新 `upstream.lock`，重新生成 protos，打标签发布。

## 16.6 发布节奏
- 核心新标签发现后自动准备候选；完整协议与关键行为检查、CI、每个候选的真实 Windows 发布闸门全部通过后发布（第 22 章），不得因赶当天发布跳过验证。
- 接口或关键常量变化、或 Apple 客户端有 UI 变化时，按 16.4 处理：目标为稳定版发布后 7 天内完成适配；受阻时记录原因，不发布未通过验证的版本。
- 核心同步可先发布，但发布说明必须分别列明核心版本、已验收 Apple 提交和未完成的界面差异。Windows 无等价能力的项目按第 15 章明确禁用、替代或省略，不承诺一定补齐。
